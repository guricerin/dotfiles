# ニュースのビューアの停止

news-view-start で起動したビューアを止める。ポート 8765 には別のプロセスが入っている可能性もあるので、ビューアのプロセスだと確かめてから止める。

## 停止条件（最優先）

次のどれかに当てはまったら、作業を進めずに止まり、「停止時の報告」の形でユーザーに返す。推測で埋めて先に進まない。

- **わからない**:
  - 該当なし（理由: 止める対象は「ポート 8765 で待ち受ける `serve_news.ts` のプロセス」と決まっていて、ユーザーから受け取る情報がないため）
- **矛盾している**:
  - ポート 8765 で待ち受けているのが `serve_news.ts` ではないプロセス（ユーザーはビューアを止めたいが、実際に動いているのは別のもの）
- **承認が必要**:
  - 該当なし（理由: 止めるのはローカルのビューアだけで、news-view-start でいつでも起動し直せるため）
- **想定外**:
  - `kill <PID>` が失敗した（権限がないなど）
  - `kill <PID>` から5秒たっても、ポート 8765 で待ち受けたまま

### 停止時の報告

- 事実: 確認できたこと（出典: ファイル名・コマンドの出力・ユーザーの発言）
- 推測: 事実から推測したこと（根拠つき）
- 止まった理由: 上のどの停止条件に当たるか
- 決めてほしいこと: 選択肢と、それぞれを選んだときの影響

## 事実と推測の扱い

- 推測には「推測:」と明記し、根拠を添える。出典を示せないことは事実として書かない
- 推測を前提に、取り消せない操作をしない

## 入力

ユーザーからの入力はない。止める対象は、ポート 8765 で待ち受けている `serve_news.ts` のプロセス（`lsof` と `ps` の出力から特定する）。

## 手順

1. **ポートで待ち受けているプロセスを確かめる。** 止める対象を特定するため。

   ```bash
   lsof -nP -iTCP:8765 -sTCP:LISTEN
   ```

   出力が空なら、ビューアはもう止まっている。何もせずにそう伝えて終わる。

2. **ビューアのプロセスか確かめる。** `lsof` の COMMAND 欄は `bun` としか出ないので、引数まで見て `serve_news.ts` だと確認する。別のプロセスを止めないため。

   ```bash
   ps -o pid,command -p <PID>
   ```

   `serve_news.ts` が含まれなければ停止条件に従う。

3. **止める。** まずは通常の終了（SIGTERM）で止める。`kill -9` は使わない。

   ```bash
   kill <PID>
   ```

4. **止まったことを確かめる。** 終了まで少しかかることがあるので、0.5秒おきに最大10回確かめる。

   ```bash
   for i in $(seq 10); do lsof -nP -iTCP:8765 -sTCP:LISTEN >/dev/null || break; sleep 0.5; done; lsof -nP -iTCP:8765 -sTCP:LISTEN
   ```

   出力が空なら止まっている。

   バックグラウンドで起動していた場合は、このあと「終了コード 143 で失敗」という通知が届く。143 は SIGTERM で止めたときのコードなので、問題ない。

## 出力先

会話に、止めたかどうかを一行で返す。もともと止まっていた場合は、そう伝える。終了コード 143 の通知が届いたら、止めたことによるもので問題ないと一言添える。

## 終わりの条件

`lsof -nP -iTCP:8765 -sTCP:LISTEN` の出力が空であれば完了。停止条件で止まった場合は完了ではない。

## やらないこと

このスキルの中では、承認があっても次のことはしない。必要な場合は、スキルの外で別の作業としてユーザーに指示してもらう。

- `serve_news.ts` 以外のプロセスを止める
- `kill -9` や `pkill`・`killall` で、名前の一致だけを頼りにまとめて止める
- ニュースのまとめのファイルを消す・書き換える
