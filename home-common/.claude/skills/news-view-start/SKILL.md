# ニュースのビューアの起動

news-digest が出力したまとめを、ブラウザで一覧から選んで読めるようにする。ビューアは本人が頼んだときだけ起動するもので、常に動かしておくものではない。

## 停止条件（最優先）

次のどれかに当てはまったら、作業を進めずに止まり、「停止時の報告」の形でユーザーに返す。推測で埋めて先に進まない。

- **わからない**:
  - 表示するフォルダとして相対パスや曖昧な名前（例: 「いつもの場所」「この前のフォルダ」）が指定され、どのフォルダを指すか決められない
- **矛盾している**:
  - ビューアがすでに起動しているが、ユーザーが指定したフォルダと違うフォルダを表示している（`ps` の `--dir` の値で分かる）。今のビューアを止めて起動し直すか確認する
- **承認が必要**:
  - 該当なし（理由: 起動するのは `127.0.0.1` だけで待ち受けるローカルのサーバーで、外部への送信も費用もなく、news-view-stop でいつでも止められるため）
- **想定外**:
  - ポート 8765 を `serve_news.ts` 以外のプロセスが使っている
  - `bun` が見つからない
  - `serve_news.ts` が見つからない（news-digest のスキルが入っていない）
  - 表示するフォルダが存在しない
  - 起動したのに、5秒待っても `curl` が `200` を返さない、またはプロセスがすぐ終了した

### 停止時の報告

- 事実: 確認できたこと（出典: ファイル名・コマンドの出力・ユーザーの発言）
- 推測: 事実から推測したこと（根拠つき）
- 止まった理由: 上のどの停止条件に当たるか
- 決めてほしいこと: 選択肢と、それぞれを選んだときの影響

## 事実と推測の扱い

- 推測には「推測:」と明記し、根拠を添える。出典を示せないことは事実として書かない
- 推測を前提に、取り消せない操作をしない

## 入力

- 表示するフォルダ（任意）: 絶対パス、または `~` から始まるパス。指定がなければ news-digest のデフォルトの出力先（`~/workspace/github.com/guricerin/pkb/news/output/`）。サーバーも `--dir` を省くとこのフォルダを表示する
- ビューアのスクリプト: `~/.claude/skills/news-digest/scripts/serve_news.ts`（news-digest のスキルに含まれる）

## 手順

1. **ポートの状態を確かめる。** 二重に起動したり、ほかのプロセスとぶつかったりしないため。

   ```bash
   lsof -nP -iTCP:8765 -sTCP:LISTEN
   ```

   出力があれば、その PID のコマンドを `ps -o pid,command -p <PID>` で確かめる。`serve_news.ts` ならもう起動しているので、手順 4 に進んで URL を返すだけでよい。別のプロセスなら停止条件に従う。出力が空なら次へ。

2. **前提を確かめる。** 起動に失敗してから原因を探すより、先に分かるため。`command -v bun` で bun があること、`serve_news.ts` があること、表示するフォルダがあることを確かめる。どれかがなければ停止条件に従う。

3. **バックグラウンドで起動する。** 会話の応答を止めないため。Bash の `run_in_background` で起動する。フォルダの指定がなければ `--dir` は付けない。

   ```bash
   bun ~/.claude/skills/news-digest/scripts/serve_news.ts [--dir <表示するフォルダ>]
   ```

   サーバーは `127.0.0.1:8765` だけで待ち受ける。左に一覧（新しい順）、右に本文を表示する。一覧はアクセスのたびに読み直すので、まとめを足しても再起動は要らない。まとめの中の生の HTML は文字として表示し、リンクは http・https・mailto だけを有効にしている（フィード由来の文章をブラウザで実行させないため）。

4. **起動を確かめて URL を返す。** 起動直後はまだ待ち受けていないことがあるので、0.5秒おきに最大10回確かめる。

   ```bash
   for i in $(seq 10); do c=$(curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8765/); [ "$c" = 200 ] && break; sleep 0.5; done; echo $c
   ```

   `200` が返ったら、URL を伝える。

## 出力先

会話に、次を短く返す。

- URL: `http://127.0.0.1:8765/`
- すでに起動していた場合は、そのことを一言添える
- 止めるときは「ビューア止めて」（news-view-stop）と言えばよいこと

## 終わりの条件

`curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8765/` が `200` を返し、`lsof -nP -iTCP:8765 -sTCP:LISTEN` の PID が `serve_news.ts` のプロセスであれば完了。停止条件で止まった場合は完了ではない。

## やらないこと

このスキルの中では、承認があっても次のことはしない。必要な場合は、スキルの外で別の作業としてユーザーに指示してもらう。

- ビューアを `127.0.0.1` 以外で待ち受けさせる、トンネルなどで外部に公開する（まとめは本人だけが見るもので、公開しない前提で作っているため）
- ポート 8765 を使っているほかのプロセスを止める
- ニュースのまとめを新しく作る（news-digest の役割のため）
- ログイン時の自動起動など、常駐させる設定をする
