# ニュースのまとめと表示

news-digest と news-view-start を順番に実行し、まとめを作ってすぐにブラウザで読める状態にする。本人は毎回この2つを続けて頼んでいるので、1回の指示で済むようにする。

## 停止条件（最優先）

次のどれかに当てはまったら、作業を進めずに止まり、「停止時の報告」の形でユーザーに返す。推測で埋めて先に進まない。

- **わからない**:
  - news-digest または news-view-start の停止条件の「わからない」に当たった（例: 出力先に曖昧な名前が指定され、どのフォルダを指すか決められない）
  - 両方の SKILL.md を読めず、手順が分からない
- **矛盾している**:
  - news-digest または news-view-start の停止条件の「矛盾している」に当たった（例: ビューアがすでに起動しているが、今回の出力先とは別のフォルダを表示している）
- **承認が必要**:
  - news-digest の停止条件の「承認が必要」に当たった（例: 出力先フォルダがない、同名ファイルがある、Git で管理されているフォルダに出す）。確認が取れれば続けてよい
- **想定外**:
  - news-digest または news-view-start の停止条件の「想定外」に当たった（例: スクリプトがエラーで終わった、ポート 8765 をほかのプロセスが使っている）
  - news-digest が完了しなかった。この場合は news-view-start に進まない。古いまとめだけを表示して、新しいまとめができたように見えるのを防ぐため

### 停止時の報告

- 事実: 確認できたこと（出典: ファイル名・コマンドの出力・ユーザーの発言）
- 推測: 事実から推測したこと（根拠つき）
- 止まった理由: 上のどの停止条件に当たるか。news-digest と news-view-start のどちらで止まったかも書く
- 決めてほしいこと: 選択肢と、それぞれを選んだときの影響

## 事実と推測の扱い

- 推測には「推測:」と明記し、根拠を添える。出典を示せないことは事実として書かない
- 推測を前提に、取り消せない操作をしない

## 入力

news-digest と同じものを受け取る。どれも任意。

- 出力先フォルダ: 絶対パス、または `~` から始まるパス。指定がなければ `~/workspace/github.com/guricerin/pkb/news/output/`
- 期間: 例「直近3日」「10/14 から」。指定がなければ前回のまとめの時刻から現在まで
- 対象のグループ: 例「札幌のだけ」「Auth0 だけ」。指定がなければすべて

ビューアで表示するフォルダは、ここで決めた出力先と同じにする。

## 手順

1. **news-digest の手順を実行する。** `~/.claude/skills/news-digest/SKILL.md` を読み、その手順・停止条件・出力形式のとおりにまとめを作る。中身をここに書き写さないのは、news-digest を直したときに食い違わないようにするため。
2. **news-digest が完了したか確かめる。** news-digest の「終わりの条件」がすべて満たされていれば次へ進む。満たされていなければ、停止条件に従って止まる。
3. **news-view-start の手順を実行する。** `~/.claude/skills/news-view-start/SKILL.md` を読み、その手順どおりにビューアを起動する。出力先がデフォルトでなければ `--dir <出力先>` を付ける（ビューアが今回のまとめを表示するようにするため）。すでに `serve_news.ts` が同じフォルダで動いていれば、起動し直さずに URL を返す。一覧はアクセスのたびに読み直されるので、再起動は要らない。
4. **会話で報告する。** 下の「出力先」の形でまとめて返す。

## 出力先

- まとめのファイル: news-digest の出力先（デフォルトは `~/workspace/github.com/guricerin/pkb/news/output/<YYYY-MM-DD-HH-MM>.md`）
- 会話: 次をまとめて短く返す
  - 出力したファイルのパス、期間、件数、要チェックの見出し（news-digest の報告の内容）
  - ビューアの URL `http://127.0.0.1:8765/`。すでに起動していた場合はそのことを一言添える
  - 止めるときは「ビューア止めて」（news-view-stop）と言えばよいこと

## 終わりの条件

次の両方を満たせば完了。停止条件で止まった場合は完了ではない。

- news-digest の「終わりの条件」がすべて満たされている
- news-view-start の「終わりの条件」が満たされている（`curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8765/` が `200` を返し、ポート 8765 の PID が `serve_news.ts` のプロセス）

## やらないこと

このスキルの中では、承認があっても次のことはしない。必要な場合は、スキルの外で別の作業としてユーザーに指示してもらう。

- news-digest と news-view-start の「やらないこと」に書かれていること（まとめのコミット・外部への送信、ビューアを外部に公開する、ほかのプロセスを止めるなど）
- news-digest が完了していないのにビューアを起動する
- ビューアを止める（news-view-stop の役割のため）
