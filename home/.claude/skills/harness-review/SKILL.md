# ハーネスの改善提案

会話の履歴には「同じ指摘を何度もしている」「毎回同じ手順を頼んでいる」といった改善のヒントが残るが、本人が自分で気づくのは難しい。履歴を根拠に、CLAUDE.md・スキル・hooks・設定のどこをどう直すとよいかを提案し、本人が選べるようにする。

## 停止条件（最優先）

次のどれかに当てはまったら、作業を進めずに止まり、「停止時の報告」の形でユーザーに返す。推測で埋めて先に進まない。

- **わからない**:
  - 期間を指定されたが、始まりの日時が読み取れない（例: 「この前のあれから」）
- **矛盾している**:
  - ユーザーが指定した期間と、前回の実行時刻が食い違う（例: 「前回から」と言われたが、前回の実行の記録がない）。どの期間で見るか確認する
  - スクリプトの `warnings` に「期間の始まりが現在時刻より未来」が出た
- **承認が必要**:
  - 提案を実際にファイルへ反映すること。このスキルでは提案までで止め、反映は本人が選んだものだけを別の作業として行う
  - 履歴の中身（仕事のリポジトリの内容を含む）を、会話以外の場所（外部のサービス、pkb などのファイル）に出すこと
- **想定外**:
  - `extract_history.ts` がエラーで終わった、または出力が JSON として読めない
  - `~/.claude/projects` がない、または期間内の会話が 0 件

### 停止時の報告

- 事実: 確認できたこと（出典: ファイル名・コマンドの出力・ユーザーの発言）
- 推測: 事実から推測したこと（根拠つき）
- 止まった理由: 上のどの停止条件に当たるか
- 決めてほしいこと: 選択肢と、それぞれを選んだときの影響

## 事実と推測の扱い

- 推測には「推測:」と明記し、根拠を添える。出典を示せないことは事実として書かない
- 推測を前提に、取り消せない操作をしない
- 提案にはそれぞれ根拠（どのプロジェクトの、いつの会話で、何回起きたか）を付ける。根拠が 1 回しかないものは「様子見」に分ける

## 入力

- 期間（任意）: 「直近 3 日」「10/20 から」など、始まりが読み取れるものだけを指定とみなす。指定がなければ、前回の実行時刻（`~/.claude/state/harness-review/last-run.json`）から今まで。前回の記録がなければ直近 7 日
- 会話の履歴: `~/.claude/projects/*/*.jsonl`（全プロジェクト。サブエージェントの会話は除く）
- 今のハーネス:
  - グローバル: `~/.claude/CLAUDE.md`、`~/.claude/settings.json`、`~/.claude/hooks/`、`~/.claude/skills/*/SKILL.md`、`~/.claude/templates/`。実体は dotfiles リポジトリ（`~/workspace/github.com/guricerin/dotfiles/home/.claude/`）にある
  - プロジェクトごと: 期間内に出てきた各プロジェクトの `CLAUDE.md`・`AGENTS.md`・`.claude/settings.json`
  - memory: `~/.claude/projects/*/memory/`

## 手順

1. **履歴を抜き出す。** 生の履歴は大きく、ツールの出力も混ざっていて読みにくいため、スクリプトで本人の発言・拒否・エラー・中断・呼ばれたスキルだけにする。期間を指定されたときだけ `--since` を付ける。

   ```bash
   bun ~/.claude/skills/harness-review/scripts/extract_history.ts [--since 2026-10-20T00:00]
   ```

   出力の `until` は手順 6 で使うので控えておく。

2. **今のハーネスを読む。** 「すでに書いてあるのに守られていない」のか「どこにも書いていない」のかで、直し方が変わるため。入力に挙げたファイルのうち、`projects` に出てきたプロジェクトの分だけ読む。

3. **改善の候補を拾う。** 次の観点で、履歴の中から繰り返し起きていることを探す。
   - **繰り返された指摘**: 本人が同じ種類の訂正や注意を 2 回以上している（例: 「日本語で」「PR は draft で」）→ CLAUDE.md・AGENTS.md への追記、または memory から CLAUDE.md への格上げ
   - **すでに書いてあるのに守られていない指示**: 書き方があいまい、置き場所が読まれない、などの原因を考える → 書き直し、または hooks で機械的に強制
   - **毎回手で頼んでいる手順**: 似た依頼が複数の会話に出てくる → スキル化
   - **スキルが呼ばれるべき場面で呼ばれていない**: 依頼の内容に合うスキルがあるのに、`totals.skills` の `claude`（Claude が自分で呼んだ回数）が増えていない → スキルの `description` の言い回しを足す。`user`（本人がスラッシュコマンドで呼んだ回数）だけが多いスキルは、本人が名前を覚えて打っているので、言い回しの問題とは限らない
   - **拒否・中断されたツール呼び出し**: 同じ種類の操作が拒否されている → CLAUDE.md に「やらないこと」を書く、または settings.json の `deny` に足す
   - **繰り返し出るエラー**: 同じコマンドが同じ理由で失敗している（例: macOS の BSD 版コマンドとの違い）→ CLAUDE.md に注意を書く、または手順をスクリプトにする
   - **古くなった・矛盾している指示**: CLAUDE.md・AGENTS.md・memory・スキルの間で食い違っている、または今の運用と合わない
   - **使われていないスキル**: `~/.claude/skills/` にあるのに `totals.skills` に出てこない（本人も Claude も呼んでいない）もの。期間が短いと判断できないので、期間が 2 週間以上のときだけ挙げる

   許可確認を減らす allowlist の提案は `fewer-permission-prompts` に任せ、ここでは「それを実行するとよい」と書くだけにする。役割が重なるため。

4. **提案を絞って並べる。** 効果が大きく手間が小さいものから、多くても 7 件ほどにする。本人は説明を全部読めるとは限らないので、数を増やさない。根拠が 1 回だけのものは「様子見」に回す。

5. **会話で報告する。** 「出力先」の形で返す。反映はしない。

6. **前回の実行時刻を保存する。** 次回の「前回から」の起点にするため。手順 5 まで終わったときだけ、手順 1 の `until` を保存する。停止条件で止まったときは保存しない（見ていない期間が抜けるため）。`--since` で過去の一部だけを見たときも保存しない。

   ```bash
   bun ~/.claude/skills/harness-review/scripts/extract_history.ts --mark-done <手順 1 の until>
   ```

## 出力先

会話だけに返す。ファイルには書かない（履歴には仕事のリポジトリの内容も含まれるため）。形式の例:

```
期間: 2026-10-28 14:49 〜 2026-11-04 14:49（前回の実行から）／会話 22 件・9 プロジェクト

## 結論
いちばん効きそうなのは 1 と 2。どれを反映するか番号で教えてください。

## 提案
1. **PR の assignee 漏れを hooks で防ぐ**（対象: ~/.claude/settings.json）
   - 根拠: dotfiles・pkb の会話で計 3 回「assignee 入れて」と指摘（11/1, 11/2, 11/3）
   - 直し方: …
   - 手間: 小
2. …

## 様子見（根拠が 1 回だけ）
- …

## 問題なさそうなこと
- …
```

本人が番号を選んだら、反映は別の作業として、それぞれのリポジトリのルール（ブランチを切って PR を作るなど）に従って進める。

## 終わりの条件

次がすべて確認できたら完了。停止条件で止まった場合は完了ではない。

- 「出力先」の形で、根拠つきの提案を会話に返した（提案がなければ「今回は改善案なし」と返した）
- 期間の指定がなかったときは、`~/.claude/state/harness-review/last-run.json` の `last_run` が手順 1 の `until` になっている

## やらないこと

このスキルの中では、承認があっても次のことはしない。必要な場合は、スキルの外で別の作業としてユーザーに指示してもらう。

- CLAUDE.md・AGENTS.md・スキル・hooks・settings.json・memory を変更する（このスキルは提案まで）
- 提案や履歴の中身を、pkb などのファイルや外部のサービスに書き出す
- 会話の履歴ファイル（`~/.claude/projects/*/*.jsonl`）を変更・削除する
