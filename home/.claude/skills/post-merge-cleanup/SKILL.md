# Post-merge cleanup

PR がマージされた後の定型作業（デフォルトブランチへ戻る → 最新化 → 作業用ブランチ削除）を安全に行う。ブランチ削除は取り消しにくいので、「本当にマージ済みか」「まだ push していない作業が残っていないか」を確かめてから消すのがこのスキルの肝。

## 停止条件（最優先）

次のどれかに当てはまったら、作業を進めずに止まり、「停止時の報告」の形でユーザーに返す。推測で埋めて先に進まない。

- **わからない**:
  - すでにデフォルトブランチにいて、どのブランチを片付ければよいか会話からも分からない
  - `gh pr view` で作業用ブランチの PR が見つからない
- **矛盾している**:
  - ユーザーは「マージした」と言っているが、PR の `state` が `MERGED` ではない
  - ローカルの作業用ブランチの先端が PR の最終コミット（`headRefOid`）と一致しない（push していないコミットが残っている可能性がある）
  - リモートの作業用ブランチの先端が `headRefOid` と一致しない（マージ後に誰かが push した可能性がある）
- **承認が必要**:
  - PR がないブランチを消すこと（例: 試しに作った使い捨てブランチ）。デフォルトブランチから進んだコミットがないことを示したうえで、消してよいか確認する
  - 上の「矛盾している」に当たるブランチを、それでも消すこと
- **想定外**:
  - 未コミットの変更がある（switch で変更が持ち越されたり、切り替えに失敗したりする）
  - `git pull --ff-only` が fast-forward できない（ローカルのデフォルトブランチに独自のコミットがある）
  - ブランチが別の worktree でチェックアウトされていて削除できない
  - `gh` の認証切れやネットワークエラーなどで、コマンドが失敗した

### 停止時の報告

- 事実: 確認できたこと（出典: ファイル名・コマンドの出力・ユーザーの発言）
- 推測: 事実から推測したこと（根拠つき）
- 止まった理由: 上のどの停止条件に当たるか
- 決めてほしいこと: 選択肢と、それぞれを選んだときの影響

## 事実と推測の扱い

- 推測には「推測:」と明記し、根拠を添える。出典を示せないことは事実として書かない
- 推測を前提に、取り消せない操作をしない

## 入力

- 対象のブランチ: ユーザーがブランチ名や PR 番号を指定していればそれを使う。指定がなければ現在のブランチ（`git branch --show-current`）
- リポジトリ: 現在の作業ディレクトリの git リポジトリ。GitHub の PR 情報は `gh` で取得する

## 手順

1. **対象を特定する。** デフォルトブランチ名は `main` と決め打ちせずに取得する（`master` や `develop` のリポジトリもあるため）。`gh` が使えなければ `git symbolic-ref --short refs/remotes/origin/HEAD` から `origin/` を除いたものを使う。

   ```bash
   git branch --show-current
   gh repo view --json defaultBranchRef -q .defaultBranchRef.name
   ```

2. **PR がマージ済みか確認する。** マージ前にブランチを消すと作業が失われうるため。`state` が `MERGED` でなければ止まる。

   ```bash
   gh pr view <作業用ブランチ or PR番号> --json number,state,mergedAt,baseRefName,headRefName,headRefOid
   ```

3. **作業ツリーがきれいか確認する。** 未コミットの変更があれば止まる。

   ```bash
   git status --porcelain
   ```

4. **デフォルトブランチに switch して pull する。** `--ff-only` にするのは、ローカルのデフォルトブランチに意図しないマージコミットを作らないため。

   ```bash
   git switch <デフォルトブランチ>
   git pull --ff-only
   ```

5. **ローカルの作業用ブランチを削除する。** まず `-d` で消す。squash merge や rebase merge ではコミットハッシュが変わるため `-d` が「未マージ」として失敗するので、その場合はローカルの先端が `headRefOid` と一致することを確かめてから `-D` で消す。一致しなければ `git log --oneline <headRefOid>..<作業用ブランチ>` で差分を示して止まる。

   ```bash
   git branch -d <作業用ブランチ>
   git rev-parse <作業用ブランチ>   # -d が失敗したときだけ
   git branch -D <作業用ブランチ>   # 先端が headRefOid と一致したときだけ
   ```

6. **リモートの作業用ブランチを削除する。** GitHub の「Automatically delete head branches」で消えていることが多いので、残っているときだけ消す。残っていた場合は、先端が `headRefOid` と一致することを確かめてから消す。最後に追跡ブランチを掃除する。

   ```bash
   git ls-remote --heads origin <作業用ブランチ>   # 出力が空なら削除済み。あれば先端のハッシュを headRefOid と比べる
   git push origin --delete <作業用ブランチ>
   git fetch --prune
   ```

7. **結果を報告する。** 何をしたかを「出力先」の形で短くまとめる。

## 出力先

会話に、実行したことを箇条書きで返す。例:

```
- main に switch して pull（abc1234 → def5678）
- ローカルブランチ feat/foo を削除（squash merge のため -D、PR #12 の head と一致を確認済み）
- リモートブランチ origin/feat/foo を削除
```

途中で止まった場合は「停止時の報告」の形で返す。

## 終わりの条件

次がすべて確認できたら完了。停止条件で止まった場合は完了ではない。

- `git branch --show-current` がデフォルトブランチを返す
- `git status -sb` でデフォルトブランチが origin と同じ（ahead / behind がない）
- `git branch --list <作業用ブランチ>` の出力が空
- `git ls-remote --heads origin <作業用ブランチ>` の出力が空

## やらないこと

このスキルの中では、承認があっても次のことはしない。必要な場合は、スキルの外で別の作業としてユーザーに指示してもらう。

- 未コミットの変更を `git stash` や `git checkout -- .` などで退避・破棄する
- デフォルトブランチに対して `reset`・`rebase`・force push をする
- 対象として特定した作業用ブランチ以外のブランチを消す
